# UI 设计规范

## 1. 设计目标

插件 UI 应像 Obsidian 原生功能一样自然存在。整体风格参考苹果公司的设计语言：简约、克制、清晰、有质感，但不脱离 Obsidian 的视觉体系。

关键词：

- 原生感。
- 留白。
- 清晰层级。
- 细线分割。
- 轻量动画。
- 亮暗主题自适应。
- 不喧宾夺主。

## 2. 布局原则

- 侧边栏优先，避免占用主编辑区。
- 高频操作放在一屏内。
- 长内容用滚动区域承载。
- 设置页按功能分组。
- 危险或高影响操作需要确认。
- AI 修改笔记必须提供预览。

## 3. 视觉原则

- 使用 Obsidian CSS 变量适配主题。
- 使用细边框和轻微背景区分区域。
- 圆角保持克制，避免过度卡片化。
- 文本层级清晰，标题、说明、正文、辅助信息区分明显。
- 不使用大面积艳丽渐变。
- 不使用花哨动效。

推荐使用的 Obsidian 变量：

```css
var(--background-primary)
var(--background-secondary)
var(--text-normal)
var(--text-muted)
var(--text-accent)
var(--interactive-accent)
var(--background-modifier-border)
var(--background-modifier-hover)
```

## 4. AI 侧边栏

侧边栏由以下区域组成：

- 顶部工具栏：当前上下文、模型选择、清空会话。
- 消息列表：用户消息、AI 消息、系统提示。
- 引用来源：折叠展示引用笔记。
- 输入区：多行输入框、发送按钮、停止按钮。

交互要求：

- 支持流式输出。
- 生成中可停止。
- 请求失败时在消息内展示错误。
- 引用来源可点击打开对应笔记。
- 当前上下文范围必须可见。

## 5. 设置页

设置页分组：

- AI 服务商。
- 默认模型。
- 上下文范围。
- Prompt 模板。
- 隐私与安全。
- 高级设置。

每组设置应包含简短说明，但不要堆砌长篇解释。

## 6. 上下文切换器

上下文切换器应清晰告诉用户 AI 当前能看什么。

展示内容：

- 范围名称。
- 范围类型。
- 文件数量估计。
- 是否允许云端模型。

状态示例：

- 当前文件。
- 工作项目文件夹。
- 今日日记。
- 读书笔记标签。
- 论文写作上下文包。

## 7. 差异预览弹窗

差异预览用于保护用户原文。

要求：

- 明确展示原文和修改后内容的差异。
- 新增内容使用柔和高亮。
- 删除内容使用低饱和警示色。
- 主按钮为确认应用。
- 次按钮为取消。
- 对批量修改展示修改摘要。

## 8. 空状态与错误状态

空状态应直接告诉用户下一步。

示例：

- 未配置模型：提示前往设置页添加 AI Provider。
- 当前上下文为空：提示切换或创建上下文范围。
- 没有选中文本：提示先选择需要处理的内容。
- 没有检索结果：提示扩大上下文范围或换一个问题。

错误状态应包含：

- 简短错误原因。
- 建议操作。
- 可选的技术细节展开区。

## 9. 动效

动效只用于反馈状态，不用于装饰。

可使用：

- 消息出现的轻微淡入。
- 面板切换的短过渡。
- 按钮 hover 状态。
- 流式输出光标。

避免：

- 大幅位移。
- 循环装饰动画。
- 复杂弹跳效果。
- 影响阅读的动效。
