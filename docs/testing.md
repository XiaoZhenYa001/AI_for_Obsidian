# Obsidian 内加载与验收清单

## 0. 自动回归与构建

在项目根目录运行：

```sh
npm install
npm test
npm run build
```

`npm test` 覆盖服务商流式解析和错误传播、请求权限、授权范围检索、完整会话保存、笔记修改与恢复冲突、Excalidraw 文本方案及 HTML 资源处理。`npm run build` 执行 TypeScript 检查并生成 `main.js`。

交互回归需要 Python 的 Playwright 包和已安装的 Chrome。在 PowerShell 中运行以下命令；每条均应独立成功：

```powershell
python -m pip install playwright
node tests/build-ui-harness.cjs
$env:PLAYWRIGHT_CHANNEL = 'chrome'
python tests/drawing-ui-smoke.py
python tests/html-ui-smoke.py
python tests/html-security-smoke.py
node tests/build-composer-harness.cjs
python tests/composer-ui-smoke.py
python tests/html-full-ui-smoke.py
python tests/html-editor-ui-smoke.py
```

如使用 Playwright 自带的 Chromium，可先运行 `python -m playwright install chromium`，并取消 `PLAYWRIGHT_CHANNEL` 环境变量。测试脚本会按需启动本地 HTTP 服务，无需另开服务器。测试页面和截图位于 `.test-output/`，不提交到版本库。

绘图交互回归验证预览不写入、修改预览文字、坐标应用、画布冲突和取消操作；HTML 交互回归验证页面交互、本地 CSS/JS/图片、源码编辑与保存、依赖刷新、网络开关与宿主隔离。HTML 安全回归单独检查页面导航和网络权限切换。`html-editor-ui-smoke.py` 在 Chrome 6 倍 CPU 降速下验证保存、草稿恢复、外部修改冲突、另存副本、取消/放弃修改、后台源码恢复，以及隐藏预览时没有额外脚本心跳和文件读取。此测试不测量真实电池功耗。

这些浏览器测试加载真实的功能模块，但以模拟对象代替 Obsidian 和 Excalidraw API。通过自动回归不代表已在真实 Obsidian 中完成验收，仍须按下列步骤检查插件注册、文件保存、原生撤销和插件之间的兼容性。

## 1. 安装位置

将项目中的以下文件放到 Obsidian vault 的插件目录：

```text
.obsidian/plugins/ai-second-brain/
├─ manifest.json
├─ main.js
└─ styles.css
```

如果是直接在插件目录开发，则确保这三个文件位于同一目录。

## 2. 加载检查

1. 打开 Obsidian 设置。
2. 进入「Community plugins」。
3. 关闭安全模式。
4. 在已安装插件列表中启用「AI Second Brain」。
5. 打开命令面板，运行 `AI: Run self check`。

通过标准：

- 自检弹窗可以打开。
- 插件运行状态显示通过。
- 能看到 Provider、上下文、模板和知识库分析状态。

## 3. Provider 验收

至少配置一个 Provider：

- OpenAI-compatible：填写 Base URL、API Key、模型名。
- Anthropic Claude：填写 API Key、模型名。
- Ollama：确认本地 Ollama 服务已启动，并填写模型名。

通过标准：

- 设置页可以添加、编辑、删除 Provider。
- 可以设置默认聊天服务和默认编辑服务。
- 侧边栏发送问题后能收到回答。
- 开启流式输出时，回答会逐步显示。
- 点击停止按钮后生成会停止。
- 连续提问时，AI 能参考最近几轮对话。
- 点击“新对话”后，旧消息不会混入新会话。
- 第一条问题发送完成后，会话标题会自动更新。
- 切换会话后，消息、上下文范围和未发送输入草稿都能正确恢复。
- 从旧版本升级时，原有聊天记录会迁移为一个历史会话。
- 关闭并重新打开侧边栏后，当前会话和历史会话仍会显示。
- AI 回复完成后，标题、列表、代码块和表格会按 Markdown 渲染。
- 请求失败或流式连接异常中断时，应显示错误，不应显示为成功回答。
- 停止或失败时，已接收的部分回答仍保留；重新打开侧边栏后状态不丢失。

## 4. 上下文范围验收

在设置页创建不同上下文范围：

- 当前文件。
- 指定文件。
- 文件夹。
- 标签。
- 路径规则。

通过标准：

- 侧边栏顶部可以切换上下文。
- “当前文件”范围直接显示实时文件名，不显示泛化的“当前文件”文案。
- 单文件范围显示实际文件名；多文件范围显示前两个文件名和总数，悬浮可查看完整路径。
- 点击单个授权文件名可以直接打开笔记；多文件范围会打开可按名称或路径搜索的文件列表。
- 打开、创建、删除或重命名笔记后，授权文件显示会同步刷新。
- 对话引用来源只来自当前授权范围。
- 关闭「允许云端模型」后，云端 Provider 不应读取该范围。
- 即使关闭本次请求的上下文检索，“允许云端模型”的限制仍生效。
- 授权范围之外的嵌入笔记和反向链接来源不应进入模型上下文。

## 5. 本地索引验收

运行命令：

- `AI: Rebuild local text index`
- `AI: Run self check`

通过标准：

- 重建索引命令会提示索引了多少文件和片段。
- 自检弹窗中能看到本地文本索引状态。
- 修改、删除或重命名 Markdown 文件后，相关文件索引会自动失效。
- 不手动重建也可以使用问答；插件会在搜索前自动补齐缺失索引。
- 从大范围切换到较小范围后，小范围内的相关文件仍可命中，不受旧范围缓存数量影响。
- 修改笔记链接、等待 Obsidian 元数据解析完成后，反向链接结果应更新。

## 6. 编辑器操作验收

在编辑器中选中文本，右键执行：

- AI 解释选中文本。
- AI 总结选中文本。
- AI 改写选中文本。
- AI 翻译选中文本。
- AI 扩写选中文本。
- AI 缩写选中文本。

通过标准：

- 解释和总结会追加 AI 说明。
- 改写、翻译、扩写、缩写会先显示差异预览。
- 点击取消不会修改原文。
- 点击应用后替换选区。
- Obsidian 撤销可以回退修改。
- AI 处理期间移动光标不会改变原先锁定的修改范围。
- AI 处理期间修改原文或切换笔记后，点击应用会被阻止并给出提示。
- 差异预览中单独按 Enter 不会直接应用修改。

## 7. 笔记生成验收

运行命令：

- `AI: Generate content`
- `AI: Generate new note`

通过标准：

- 可以输入提示词并生成 Markdown 预览。
- 可以选择是否使用当前上下文。
- 在编辑器中运行时，可以把生成内容插入当前光标。
- 生成期间笔记内容发生变化时，插入操作会被阻止，避免覆盖新内容。
- 创建新笔记时，会生成到 `AI Second Brain/` 文件夹。
- 使用上下文时，预览区下方会显示引用来源。

## 8. 知识库分析验收

运行命令：

- `AI: Analyze knowledge health`
- `AI: Generate MOC draft`
- `AI: Generate daily review draft`
- `AI: Generate weekly review draft`

通过标准：

- 健康检查弹窗能显示孤立笔记、缺摘要、补链建议和高频标签。
- 点击报告中的笔记可以打开文件。
- MOC 草稿会生成到 `AI Second Brain/` 文件夹。
- 每日/每周回顾草稿会生成到 `AI Second Brain/` 文件夹。

## 9. 可编辑图谱验收

准备：安装并启用 Obsidian Excalidraw 插件，确保其 ExcalidrawAutomate API 可用。

入口：

- 命令面板运行 `AI: Generate Excalidraw diagram`。
- 编辑器右键悬浮“AI 询问”，选择“生成图谱”。
- 在一条已完成的 AI 回复下点击“生成图谱”。

通过标准：

- 可选择思维导图、流程图、知识关系图或时间线，以及横向/纵向布局。
- 来源选项显示实际当前笔记文件名；从 AI 回复进入时显示“当前 AI 回复”。
- 点击“生成结构”后先显示节点、关系和来源数量，未确认前不创建文件。
- “布局”视图显示与横向/纵向设置一致的节点和连线，并只在预览区域内部滚动。
- “节点”“关系”“来源”视图内容完整，长名称不会撑宽弹窗。
- 点击来源项可以打开对应的 Markdown 原始笔记。
- 修改节点名称或类型后，“布局”视图会立即使用新结构重新排版。
- 修改标题或横向/纵向布局不会丢弃草稿，也不会再次请求 AI。
- 删除节点会同步移除相关关系，且最后一个节点不能删除。
- 可以增删关系、调整起点和终点、修改关系说明；自环和重复关系会被拒绝。
- 手动调整草稿不会再次请求 AI。
- 生成期间按钮切换为“停止生成”；停止后可以重新生成，关闭弹窗不会继续更新界面。
- 生成期间修改类型、来源、方向、标题或绘图重点后，旧请求结果不会覆盖新设置。
- 创建期间按钮进入锁定状态，连续点击不会生成重复文件。
- 创建的 Excalidraw 图形可以继续移动、编辑，带来源的节点可跳转到原笔记。
- 勾选“嵌入当前笔记”后只插入绘图链接；生成期间笔记或当前文件变化时拒绝写入。
- 禁用 Excalidraw 后再次生成，会明确降级为 Mermaid 笔记且可正常打开。
- 亮色、暗色主题下节点、连线、按钮和结构预览均清晰，无横向溢出。

## 10. 亮暗主题验收

分别切换 Obsidian 亮色和暗色主题。

通过标准：

- 侧边栏、设置页、差异预览、自检弹窗和健康检查弹窗文字可读。
- 边框、背景、引用来源和状态徽标跟随 Obsidian CSS 变量。
- 文本没有明显重叠或溢出。
- AI 回复中的长代码和表格只在内容区域内部滚动，不撑宽侧边栏。
- 系统开启“减少动态效果”后，加载点、光标和操作按钮不再播放动画。

## 11. 编辑已有 Excalidraw 画布

准备：安装并启用 Excalidraw 插件，创建含标题、独立文本、带文字矩形和带标签箭头的画布，保存为 `.excalidraw` 或 `.excalidraw.md`。AI 模式需配置可用的编辑 Provider；直接插入文本不需要模型请求。

操作与通过标准：

1. 运行 `AI: Edit Excalidraw drawing`，文件右键菜单“AI 编辑画布内容”和对话输入框旁的画布按钮均应进入聊天侧栏，不出现独立编辑面板。默认当前或对话绑定的画布；没有目标时才选择文件，不默认库内第一张画布。输入框上方显示目标，可切换或退出画布编辑。
2. 发送“在‘项目计划’标题下方添加‘本周目标’”。生成结果应在消息里显示新增文本或修改前后内容，以及“写入画布”“放弃”；不显示坐标、字号或输入方式表单。生成期间和待确认期间，绘图内容保持原样，源码和画布仍可编辑，视角可自由平移缩放。
3. 继续发送“再简短一点”，应调整尚未写入的完整方案，旧预览失效，只有最新方案可写入。点击“写入画布”一次应用完整结果，其他元素保持不变；点击“撤销本次写入”或在 Excalidraw 中原生撤销应恢复原内容。连续点击写入不应重复插入。
4. 在 Excalidraw 中选中一个文本元素，要求“将选中的文字改为‘已完成’”。验证目标正确；修改容器或箭头标签时，原容器和箭头几何形状保持不变。
5. 在完整 AI 回复下点击“插入 Excalidraw 画布”，应直接插入完整回复且不调用模型。选中元素时插入在选区下方，多选时依据整个选区边界；无选区时插入当前视野中心，缩放和平移后仍正确。坐标不需要用户填写。
6. 生成或预览期间手动改动画布，应保留手改内容并拒绝写入旧方案。写入后继续改动画布，聊天撤销应拒绝覆盖，提示使用原生撤销。生成后切换当前文件，确认仍写入原目标；目标被关闭、移动或删除时应拒绝写入。
7. 通过对话发送 `/draw 在 x=200、y=300 添加“你好”`，确认进入编辑预览。当前范围仅有该画布时，明确修改指令可直接进入；普通解释问题仍应得到对话回答。
8. 在对话中引用“上面的总结”时，检查生成的文本符合近期完整回答。预览原样显示文本中的 Markdown 标记，不将这些标记隐藏为排版效果。
9. 生成期间点击“停止”、关闭聊天或断开模型连接，画布应保持原样。待确认时放弃、退出画布编辑、切换会话或关闭侧栏，也应没有文件写入。切回或重开聊天后只显示失效记录，不恢复可应用的旧按钮。插件卸载后无遗留计时器或输入拦截。
10. 禁用 Excalidraw 后尝试编辑，应明确提示需要插件。通用笔记修改方案应拒绝把绘图文件当作 Markdown 覆盖。

此功能仅支持新增和更新文本。不要以删除图形或重排任意图形作为本轮通过标准。真实集成还应验证原生撤销只需一步即可恢复整批修改、带容器的文本撤销恢复原尺寸、独立窗口的当前目标正确，以及原先只读的画布保持只读。浏览器夹具不能代替真实 Obsidian 与 Excalidraw 集成验收。

## 12. HTML 页面预览

先在插件设置的“HTML 预览”打开“启用 HTML 原生预览”，再重新加载插件。确认默认关闭、开启后持久化、关闭时所有预览页立即关闭，重新加载插件后不再接管扩展名。文件默认打开方式的变更需要重新加载插件。

完整模式按原文渲染 HTML，以页面所在文件夹作为资源根。新增浏览器回归验证相对模块导入、JSON fetch、本地存储、动态脚本、表单、srcset、嵌入页面与在线资源开关。可将工具栏切换为“隔离预览”验证旧模式。

准备一个库内 `demo/page.html`，包含按钮计数器、相对路径 CSS、JS、图片及一个外部图片地址。可加入本地 CSS 的 `@import`，以检查依赖刷新。

操作与通过标准：

1. 打开 `.html` 或 `.htm` 文件，应出现预览。另检查 `AI: Preview HTML file` 和文件右键“预览 HTML 页面”；即使其他插件接管扩展名，显式预览入口也应可用。
2. 点击计数按钮，确认内联和本地 JS 可运行，CSS 与图片正常显示；源码标签应可编辑。修改后点击“保存”或 Ctrl/Cmd+S，确认原文件内容变化，返回预览看到修改结果。
3. 修改 HTML 文件和已加载的本地 CSS/JS/图片，确认预览自动刷新；点击“刷新”也应重新加载。
4. 初次打开时，“允许在线资源”未勾选，外部资源不应加载。勾选后允许外部资源请求；关闭该选项后立即结束旧页面，再使用离线预览。切换文件或关闭后重新打开时，该选项应恢复关闭；工具栏“刷新”保留当前选择。
5. 页面脚本尝试访问宿主 DOM 或 Node `require` 时，不应取得访问能力。测试时不要在页面中放入真实密钥或敏感数据。
6. 在对话中要求生成自包含 HTML 页面，等待回答完成，再点击“保存 HTML 并预览”。应在 `AI Second Brain/HTML/` 创建文件并打开；只显示回答时不应自动创建文件。
7. 输入未保存源码后关闭并重新打开，确认本机草稿恢复；在另一编辑器修改原文件，确认保存拒绝覆盖，另存副本保留草稿。放弃修改需要确认，取消应保留文本。
8. 默认“隐藏时暂停”开启：切到源码或隐藏标签页后，页面计时、动画、音频应停止；返回预览重新加载。取消该选项后允许持续运行。隐藏源码页期间从外部修改文件，再切回源码应更新干净文本，或保留草稿并提示冲突。
9. 在真实 Obsidian 的省电模式下检查长回复、较大授权范围和 HTML 编辑。自动测试仅模拟 Obsidian API，CPU 降速不能替代宿主集成与实际功耗测量。
10. 模拟本机草稿存储空间不足，关闭编辑器应在原文件旁创建恢复副本；如果写盘也失败，关闭后仍应弹出可复制的源码窗口。两个分支均包含在编辑器浏览器回归中。
7. 关闭预览页后，应清理 iframe 和监听器，后续文件修改不应继续更新已关闭视图。
8. 亮暗主题及窄窗口中，工具栏和源码区域应可用，页面长内容应在预览区域内部滚动。

HTML 使用 sandbox iframe 与内容安全策略隔离，默认离线。完整模式支持模块相对 `import`、当前会话内存储和嵌套页面，原始内容不被删除；隔离模式仍限制这些能力。在线资源需要手动开启。完整模式不提供业务后端，不绕过 API CORS 或远程网页禁止嵌入的策略；关闭页面后，本地预览服务和会话结束。

输入框回归：在 320、550、900px 宽度下，输入框应独占一行、按钮位于下一行、无横向溢出；输入长文本后发送、画布和停止操作仍可用。

## 13. 会话保存与归档

- 创建超过 30 个会话，在其中一个会话积累超过 60 条消息。重新启动 Obsidian 后，全部会话和消息仍应保留。
- 长会话初始显示最近 60 条，点击“加载更早的消息”可继续读取历史；切换会话后加载范围应重新初始化。
- 在“切换对话”弹窗归档一个会话，普通列表中应隐藏它；点击“显示已归档对话”可找到并恢复，消息和上下文设置均保留。
- 搜索或切换归档列表后使用批量“全选”，只应选择当前筛选中可见的会话。
- 停止一次回答并制造一次 Provider 错误，重启后检查状态与已有内容。后续模型历史应排除这些不完整回答。
- 快速切换会话、更新草稿和发送消息后重启，最近保存的状态不应被较早的异步写入覆盖。

历史完整保存与发给模型的历史窗口独立处理；每次请求仍只使用经过筛选的近期历史。

## 14. 笔记批量修改与恢复冲突

在测试库中准备可丢弃的 Markdown 文件，在 AI 回复下点击“创建修改计划”生成预览。应用后可运行 `AI: Undo last modification batch` 撤销，再检查：

- 预览后编辑原文，应用应拒绝覆盖新内容；更新前的内容比对应在实际写入时再次验证。
- 连续触发应用或撤销不应并发执行同一批操作。
- 应用后再人工修改文件，撤销应提示冲突，保留人工编辑。
- 重命名后在旧路径新建文件，撤销重命名应拒绝覆盖它，并保留待恢复记录。
- 部分恢复失败时，已恢复项不应被再次破坏，未完成项应保留以供重试；新批次不应替换尚未完成的恢复记录。
- 重启后，待恢复状态和快照应可继续使用。

自动测试还通过模拟写入或持久化失败验证上述边界。Obsidian 的重命名和删除 API 不提供与内容更新等价的原子比较写入，手验中仍需覆盖这些操作的冲突提示。
