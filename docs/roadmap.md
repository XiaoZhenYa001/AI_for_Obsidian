# 开发路线图

## 阶段 0：文档与项目骨架

目标：明确产品范围、技术架构和开发顺序。

交付物：

- 产品需求文档。
- 技术架构文档。
- UI 设计规范。
- 实施任务清单。
- Obsidian 插件基础工程结构。

完成标准：

- 文档能指导后续实现。
- 项目可以构建一个最小插件入口。

## 阶段 1：MVP 基础能力

目标：让用户可以完成最基本的 AI 对话和选中文本操作。

功能：

- 插件加载与设置页。
- Provider 配置。
- AI 侧边栏。
- 手动输入 Prompt 并获得回答。
- 命令面板打开侧边栏。
- 选中文本后执行总结、解释、改写。

完成标准：

- 用户填入 API 配置后可以完成一次 AI 请求。
- 侧边栏可以展示多轮对话。
- 编辑器选中文本可以触发 AI 操作。

## 阶段 2：上下文范围与本地检索

目标：让 AI 能基于授权笔记回答问题。

功能：

- 上下文范围数据结构。
- 当前文件、指定文件夹、标签范围。
- 上下文切换器。
- 本地 Markdown 分块。
- 文本检索。
- 回答引用来源。

完成标准：

- AI 只使用当前激活范围内的笔记。
- 回答中可以看到引用文件。
- 未授权笔记不会进入 Prompt。

## 阶段 3：差异预览与安全编辑

目标：让 AI 修改笔记时可控、可撤销。

功能：

- 差异预览弹窗。
- 确认后应用修改。
- 支持取消。
- 支持 Obsidian 撤销。
- 批量修改前显示摘要。

完成标准：

- AI 不会静默覆盖笔记。
- 用户可以清楚看到修改内容。

## 阶段 4：Prompt 模板与任务模型

目标：降低重复 Prompt 编写成本。

功能：

- 内置 Prompt 模板。
- 自定义模板。
- 模板绑定模型。
- 模板绑定上下文范围。
- 模板指定输出方式。

完成标准：

- 用户可以创建和复用常用 AI 工作流。
- 不同任务可使用不同模型。

## 阶段 5：知识库维护能力

目标：让插件真正辅助管理第二大脑。

功能：

- 知识库健康检查。
- 孤立笔记检测。
- 重复内容发现。
- 双链建议。
- MOC 页面生成。
- 每日和每周回顾。

完成标准：

- 插件可以主动给出知识库结构维护建议。
- 用户可以一键生成或更新索引页。

## 阶段 6：可编辑视觉图谱

目标：把笔记结构和 AI 分析结果转化为可继续编辑的视觉资产。

功能：

- 思维导图、流程图、知识关系图和时间线。
- AI 输出受约束的图谱结构，本地完成校验与布局。
- ExcalidrawAutomate 创建可编辑绘图。
- 节点链接回来源笔记。
- 未安装 Excalidraw 时降级为 Mermaid。

完成标准：

- 用户可在创建前检查节点、关系和来源。
- 图谱只引用本次授权或已有引用中的文件。
- 嵌入笔记前校验原文档状态，避免覆盖并发修改。

## 阶段 7：向量检索与本地模型增强

目标：提升大知识库问答质量和隐私能力。

功能：

- Embedding Provider。
- 本地向量索引。
- 混合检索。
- Ollama 本地模型。
- 敏感文件仅本地模型策略。

完成标准：

- 大型知识库检索更准确。
- 隐私敏感内容可不发送到云端。
