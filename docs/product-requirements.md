# Obsidian AI 插件产品需求文档

## 1. 产品定位

本插件为 Obsidian 提供 AI 能力，使用户可以围绕自己的本地 Markdown 知识库进行问答、创作、编辑、整理和跨笔记分析。

它不是单纯的聊天窗口，而是一个受用户控制的知识助手。插件应尊重 Obsidian 的本地优先理念，让用户明确配置 AI 可访问的笔记范围，并在发送内容到外部 AI 服务前保持可控、可解释、可追溯。

## 2. 目标用户

- 长期使用 Obsidian 进行知识管理、写作、学习或项目管理的用户。
- 希望用 AI 整理大量 Markdown 笔记的用户。
- 对隐私、文件访问边界、模型成本有明确要求的用户。
- 希望同时使用云端模型和本地模型的进阶用户。

## 3. 核心使用场景

### 3.1 对话与问答

用户可以在侧边栏或浮动面板中与 AI 对话。AI 可以读取用户授权的笔记文件夹、标签范围或单个文件，并基于这些上下文回答问题。

基础能力：

- 多轮对话。
- 当前笔记问答。
- 指定文件或文件夹问答。
- 基于标签或路径规则的知识库问答。
- 回答中展示引用来源，并支持跳转到原笔记。

### 3.2 笔记创作与生成

AI 可以根据提示词在当前笔记或新建文件中生成内容。

典型操作：

- 续写段落。
- 生成文章大纲。
- 生成会议记录模板。
- 根据关键词扩写成文章。
- 生成读书笔记摘要。
- 根据日记生成复盘。
- 根据项目笔记生成周报。

### 3.3 笔记编辑与格式整理

AI 可以对现有笔记进行编辑、改写和结构化整理。

典型操作：

- 润色文本。
- 纠正错别字和语病。
- 改写为正式文体、简洁文体或学术文体。
- 翻译选中文本。
- 统一 Markdown 标题层级。
- 整理标签。
- 补全 YAML Front Matter。
- 将散乱内容重构为结构化大纲。

### 3.4 跨笔记分析与知识图谱辅助

AI 可以分析多个笔记之间的关系，辅助用户维护知识库结构。

典型操作：

- 自动建议双向链接。
- 发现孤立笔记。
- 发现重复内容。
- 识别知识盲区。
- 生成主题摘要。
- 生成每日、每周或项目回顾报告。
- 自动生成 MOC 页面。

#### 3.4.1 可编辑图谱生成

用户可以把选中文本、当前笔记、当前授权范围或一条 AI 回复转换为思维导图、流程图、知识关系图或时间线。

- AI 负责提取节点和关系，本地布局引擎负责排版。
- 安装 Excalidraw 插件时，创建可继续拖拽、编辑和补充的 Excalidraw 绘图。
- 节点可保留到来源笔记的双向链接。
- 用户可在创建前分别检查实际布局、节点、关系和来源，并明确选择是否嵌入当前笔记。
- 用户可直接修改节点名称与类型、调整关系端点与说明，并增删节点或关系。
- 手动调整节点、关系、标题或布局方向时只在本地更新，不额外调用 AI。
- 来源视图可以直接打开对应的原始笔记。
- 图谱结构生成应支持主动停止；修改绘图参数后不得应用旧请求的结果。
- 未检测到 Excalidraw 时自动创建 Mermaid 笔记，保证任务仍可完成。
- 图谱只能使用当前授权范围或当前 AI 回复已有引用中的文件路径。

### 3.5 灵活文件访问控制

这是插件的核心特性。用户可以自由配置 AI 可访问的文件范围。

支持范围：

- 当前文件。
- 单个文件。
- 指定文件夹。
- 指定标签。
- 路径规则。
- 保存好的上下文包。

用户可以随时切换当前激活的上下文范围。例如：

- 只看「工作项目」文件夹。
- 只看「今日日记」。
- 只看某本书的读书笔记。
- 使用「论文写作上下文包」。

授权透明度要求：

- 对话侧边栏必须显示实时解析出的实际文件名，不能只显示“当前文件”等抽象名称。
- 单文件范围可直接打开对应笔记；多文件范围可搜索并查看完整路径。
- 文件打开、新建、删除或重命名后，授权文件显示应同步刷新。

安全要求：

- 未授权文件不得进入检索结果。
- 未授权文件不得被发送到 AI 服务。
- 每次请求应能展示将使用的上下文范围。
- 支持对敏感文件设置永不发送到云端模型。

### 3.6 多 API 支持与配置

插件支持多个 AI 服务商，并允许用户为不同任务选择不同模型。

计划支持：

- OpenAI 兼容接口。
- Anthropic Claude。
- DeepSeek。
- 本地 Ollama。
- 自定义 OpenAI-compatible Base URL。

配置项：

- API Key。
- Base URL。
- 模型名称。
- 温度。
- 最大输出长度。
- 任务默认模型。
- 是否启用流式输出。

任务模型示例：

- 日常问答使用轻量模型。
- 长文生成使用高能力模型。
- 本地隐私任务使用 Ollama。
- Embedding 使用单独模型。

### 3.7 快捷命令与右键菜单

插件应集成 Obsidian 命令面板和编辑器右键菜单。

右键操作：

- 解释。
- 翻译。
- 扩写。
- 缩写。
- 改写。
- 总结。
- 生成评论。
- 转换为正式文体。

命令面板操作：

- 打开 AI 侧边栏。
- 对当前笔记提问。
- 总结当前笔记。
- 整理当前笔记格式。
- 生成 MOC 页面。
- 重新构建本地索引。
- 切换上下文范围。

### 3.8 Prompt 模板系统

插件应提供内置模板，并允许用户自定义模板。

模板字段：

- 模板名称。
- 适用任务。
- Prompt 内容。
- 默认上下文范围。
- 默认模型。
- 输出位置。
- 是否需要差异预览。

内置模板：

- 会议纪要。
- 周报。
- 日记复盘。
- 读书笔记。
- 学术论文摘要。
- 知识卡片。
- 写作润色。
- 问题拆解。

### 3.9 引用溯源

AI 回答应尽量展示引用来源。

来源信息包括：

- 笔记文件名。
- 文件路径。
- 相关片段。
- 可跳转链接。
- 相似度或相关性说明。

引用溯源用于降低幻觉风险，并帮助用户回到原始笔记继续阅读。

### 3.10 差异预览与回滚

AI 修改笔记时，不应默认直接覆盖内容。

交互要求：

- 展示修改前后的差异。
- 用户确认后再应用。
- 支持取消。
- 应用后支持撤销。
- 对大范围批量修改，应生成修改摘要。

## 4. 非功能需求

### 4.1 隐私

- 默认不读取未授权文件。
- 默认不上传完整知识库。
- 敏感文件可设为仅本地模型可用。
- 设置页应清晰说明外部 API 请求会发送哪些内容。

### 4.2 性能

- 本地检索应优先使用索引，不应每次请求都扫描整个库。
- 大型知识库应支持增量索引。
- 侧边栏对话应支持流式响应。
- 长任务应显示进度和可取消状态。

### 4.3 可扩展性

- AI Provider 应抽象为统一接口。
- 文件范围、检索器、Prompt 模板、命令动作应模块化。
- 后续可以扩展更多模型、更多任务类型和更多索引后端。

### 4.4 可用性

- UI 跟随 Obsidian 亮色和暗色主题。
- 关键操作应有明确反馈。
- AI 修改笔记前应给用户确认机会。
- 错误信息应说明问题和下一步处理方式。

## 5. MVP 范围

MVP 优先实现：

1. 设置页配置一个或多个 AI Provider。
2. 侧边栏对话面板。
3. 上下文范围配置与切换。
4. 授权笔记的本地文本检索。
5. 基于检索片段的问答与引用来源展示。
6. 选中文本后执行解释、总结、改写。
7. AI 修改文本前显示差异预览。
8. 将选中内容、当前笔记或 AI 回复生成可编辑图谱。

暂不实现：

- 大型知识库的全局交互式知识图谱浏览器。
- 复杂 Agent 工作流。
- 多人协作。
- 云端同步。
- 自动后台定期分析。

## 6. 成功标准

- 用户可以清楚控制 AI 能访问哪些笔记。
- AI 可以基于授权笔记回答问题，并展示来源。
- 用户可以在编辑器内高效使用 AI 处理选中文本。
- 插件不会破坏原始笔记内容。
- 插件 UI 与 Obsidian 原生体验保持一致。
- 用户可以检查图谱结构，并在 Excalidraw 不可用时获得明确的 Mermaid 降级结果。
